# Hotfix обновлятора 4.1.4 — инструкция для GitHub

> Историческая инструкция для 4.1.4. Для актуальной сборки используйте инструкции 4.1.5.2: `PATCH_INSTRUCTIONS_GITHUB_RU.md`. Не запускайте старый workflow-тег повторно для установки cryptography hotfix.

Этот hotfix сохраняет номер версии приложения **4.1.4**. Он исправляет отказ установщика, когда в свойствах EXE Windows не заполнены поля `FileVersion`/`ProductVersion`, и гарантирует создание `update.log` до запуска PowerShell.

## Что заменить в репозитории

Скопируйте из архива патча с сохранением структуры:

- `updater_helper.py`
- `tests/test_extensions.py`
- `CHANGELOG_RU.md`
- `README_RU.md`

Не удаляйте `.git`, `.github` и остальные файлы проекта.

## Как пересобрать существующий релиз v4.1.4 без изменения номера

1. Сделайте Commit и Push этих файлов в ветку `main`.
2. Откройте GitHub → Actions → `Build Windows release`.
3. Нажмите `Run workflow`.
4. В поле `release_tag` оставьте `v4.1.4`.
5. Запустите workflow и дождитесь зелёной галочки.

Workflow уже использует `gh release upload --clobber`, поэтому новые `MoyaIshka.exe` и `MoyaIshka.exe.sha256` будут заменены в существующем релизе `v4.1.4`.

## Как проверить после сборки

1. Скачайте обновлённый `MoyaIshka.exe` из Release `v4.1.4`.
2. Запустите его из `%APPDATA%\MoyaIshka\update_staging`.
3. Он должен запустить отдельный PowerShell-установщик.
4. Проверьте `%APPDATA%\MoyaIshka\update.log`. Первая строка `Запуск установщика обновления 4.1.4` создаётся ещё до запуска PowerShell.
5. После успешной установки EXE должен находиться в выбранной папке, например `D:\ISH\MoyaIshka.exe`, и новая программа должна подтвердить версию 4.1.4.

Если AppData-журнал недоступен, установщик попробует создать `update.log` рядом с целевым EXE.

## Безопасность

Установщик не принимает файл только на основании даты изменения или имени. Он проверяет SHA-256 релизного файла, создаёт резервную копию старого EXE и после запуска новой копии ждёт подтверждение её внутренней версии, полного пути и SHA-256. При неудаче выполняется откат.

Проверено в этой сборочной среде: Python-компиляция и 81 автоматический тест. Фактическая замена EXE через Windows PowerShell должна быть подтверждена на целевом ПК после публикации обновлённого релиза.

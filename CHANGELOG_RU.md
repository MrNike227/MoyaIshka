# Изменения 4.1.9

- Добавлена интеллектуальная память: автоматическая классификация фактов, оценка важности, сроки действия временных сведений и метки заменённых противоречащих записей.
- Добавлено локальное семантическое извлечение воспоминаний через Ollama embeddings (nomic-embed-text) с кешем на компьютере и автоматическим гибридным поиском при недоступности модели.
- Сохранена совместимость со старым списком строк памяти; метаданные синхронизируются в зашифрованном облачном снимке и резервных архивах.
- Добавлено управление семантическим поиском и моделью в разделе «Память»; секреты и чувствительные сведения исключаются из сохранения и контекста.
- Добавлены ежедневные локальные резервные копии истории, памяти, настроек, базы знаний, навыков и плагинов.
- Резервные копии создаются через SQLite Backup API, содержат манифест SHA-256 и проходят проверку целостности.
- Добавлены ручное создание, ограничение количества хранимых копий и восстановление из ZIP через настройки.
- Перед восстановлением автоматически создаётся страховочная копия текущих данных; при сбое замены выполняется откат.
- Локальная папка копий по умолчанию вынесена на диск рядом с папкой установки; путь можно выбрать в настройках.
- Старые проверенные ZIP-архивы из AppData автоматически переносятся копированием в новый каталог и ставятся в очередь Google Drive; исходные архивы сохраняются.
- Восстановление архива сохраняет текущие параметры резервирования и выбранное местоположение копий.
- Добавлено AES-256-GCM шифрование ZIP-архивов перед отправкой в Google Drive, потоковая обработка и проверка SHA-256 после загрузки и перед расшифровкой.
- Добавлено опциональное зеркало ZIP-архивов в приватный Supabase Storage с ограничением доступа по Auth ID, TUS-загрузкой, независимой очередью и восстановлением.
- Добавлена отдельная папка «Моя ИИшка Backups» на Google Drive с возобновляемой блочной загрузкой, списком облачных копий и восстановлением из облака.
- При отсутствии сети локальные копии ставятся в очередь и автоматически отправляются после подключения; срок хранения локальных и облачных архивов настраивается отдельно.
- Google Drive используется как основное облако ZIP-копий; при включённом зеркале Supabase дополнительно хранит AES-256-GCM зашифрованные ZIP-архивы, а также синхронизирует состояние приложения.
- Сессии Google Drive и Supabase исключены из ZIP-архива, поскольку они защищены DPAPI и привязаны к Windows-профилю.
- Обновлены версия приложения, Windows-метаданные, установщик и CI-сборка до 4.1.9.

- Перевод сборки на PyInstaller onedir: один EXE и папка _internal со встроенным Python и библиотеками.
- ZIP-пакет с SHA-256 и манифестом файлов.
- Проверка PE-зависимостей из реальной папки сборки и автономный smoke test без Python в PATH.
- Автообновление заменяет всю папку приложения; проверяет файлы до переключения; сохраняет резервную копию и выполняет откат при неудачном старте.
- Релевантный выбор воспоминаний и ограничение объёма контекста перед отправкой модели.
- Улучшенные инструкции ИИ: цель запроса, факты и предположения, первопричина, риски и проверка результата.
- Скрипт проверки Windows 10 Pro 22H2 без установленного Python.
- Версия 4.1.8.5 остаётся тестовой до завершения проверок.

## 4.1.8.3 — углублённая проверка Windows DLL

- Убран самодельный PyInstaller bootloader: штатный PyInstaller 6.22.3 уже настраивает путь DLL для каталога распаковки.
- В EXE включаются только x64 VC++ runtime DLL из того же Python 3.11, которым выполняется сборка.
- Убраны локальные копии UCRT/API-set DLL: Windows 10/11 предоставляет UCRT как системный компонент.
- Добавлен рекурсивный анализ PE-импортов python311.dll, включая delay-load импорты и проверку x64.
- Перед выпуском EXE проверяется реальная загрузка извлечённого python311.dll через Windows LoadLibraryExW.
- Сборка зафиксирована на Windows Server 2022 как более консервативной базовой среде.

## 4.1.8.3 — дополнительное исправление загрузки Python DLL

- Перед загрузкой python311.dll папка распаковки EXE явно добавляется в поиск DLL Windows.
- Bootloader предварительно загружает VC++ Runtime и CRT API-set DLL из папки приложения.
- При отсутствии или невозможности загрузить обязательную runtime DLL показывается имя файла и системная ошибка Windows.
- Номер версии остаётся 4.1.8.3; опубликованный релиз и его файлы не затрагиваются этим коммитом.

## 4.1.4 — исправление установщика (hotfix)
- Отсутствие Windows FileVersion/ProductVersion больше не блокирует обновление: решающая проверка версии, пути и SHA-256 выполняется самим запущенным приложением через подтверждение запуска. Если метаданные есть, но версия в них другая, установка по-прежнему отклоняется.
- Журнал `update.log` создаётся до запуска PowerShell; при недоступности AppData установщик дополнительно пытается писать журнал в целевую папку установки.
- Ошибка запуска PowerShell записывается в журнал и не остаётся незаметной.


## 4.1.4 — надёжная установка обновлений Windows

- Исправлена запись PowerShell-скрипта обновления: теперь используется UTF-8 с BOM и корректные Windows CRLF. Ранее некорректное значение `newline` могло прервать создание установщика до запуска PowerShell, оставляя EXE только в AppData.
- Запуск из `AppData\MoyaIshka\update_staging` теперь передаёт текущий EXE отдельному установщику, завершает процесс и только после этого заменяет файл в выбранной постоянной папке.
- Установщик просит старый экземпляр из целевой папки корректно закрыться; если это не удаётся, замена отменяется без удаления старой версии.
- Перед заменой проверяются SHA-256, доступность папки и создание резервной копии. После замены проверяются SHA-256 и встроенная версия EXE.
- Новая программа запускается автоматически и подтверждает фактическую версию, путь запуска и контрольную сумму. Только после этого установка считается успешной.
- При неудачном запуске новая копия останавливается, предыдущий EXE восстанавливается из резервной копии и запускается снова.
- В настройках явно отображаются фактический путь запущенной программы и путь целевого EXE. Добавлена кнопка открытия журнала обновлений.
- Старое сообщение об успешной установке не показывается до подтверждения новой программой.
- Номер приложения: 4.1.4.

## 4.1.3 — Supabase E2E, фоновое исследование и адаптивная производительность

- Добавлено облачное хранилище на Supabase Auth + PostgreSQL RLS: один персональный зашифрованный vault на пользователя; содержимое шифруется на устройстве AES-256-GCM до отправки.
- Ключ шифрования выводится из отдельной парольной фразы через Scrypt; пароль не передаётся и не хранится в Supabase. На Windows локальная сессия защищается DPAPI.
- Автоматическая синхронизация после изменений и фоновая проверка каждые 5 минут; добавлено сравнение стабильного SHA-256 отпечатка, чтобы не загружать неизменённую копию. Добавлена проверка конкурентных изменений перед записью.
- Облачная копия включает диалоги, сообщения, память, избранные настройки и последние 1000 исследовательских материалов; API-ключи, пароли, аудио микрофона и голосовые модели исключены.
- Фоновое исследование по умолчанию запускается раз в 3 часа по четырём темам: до 10 результатов поиска и чтение не более 5 публичных страниц на тему за цикл. Библиотека знаний хранит до 1000 материалов; результаты автоматически синхронизируются с Supabase при подключённом облаке.
- Для профиля Intel Core i7-12700K / 24 ГБ RAM / GTX 1070 Ti установлен мягкий бюджет ИИ-процессов 5 ГБ и резерв 8 ГБ свободной системной RAM. При росте CPU/RAM нагрузки фоновые задачи приостанавливаются; worker-потоки имеют низкий приоритет.
- Локальная Ollama в штатном режиме ограничена 4 CPU-потоками, 4096 токенами контекста и 384 токенами ответа; при нагрузке — 2 потока и контекст 1536.
- Добавлена инструкция `SUPABASE_SETUP_RU.md` и SQL-скрипт `sql/supabase_setup.sql` с RLS-политиками. GitHub Actions теперь запускает автоматические тесты перед сборкой EXE.
- Версия приложения установлена на 4.1.3.


## 4.1.2 — исправление веб-поиска и резервные провайдеры

- Номер версии приложения оставлен 4.1.2.

## 4.1.2 — дополнение: загружаемые локальные голоса и значок Windows

- Добавлен каталог загружаемых русских голосов Piper: Ирина, Денис, Дмитрий и Руслан. Голоса скачиваются прямо из раздела «Windows и голос» в папку данных приложения; каждый ONNX-файл проверяется по SHA-256.
- Добавлены просмотр доступности голоса, прогресс загрузки, прослушивание примера, выбор локального голоса и удаление ненужной модели. После загрузки голос становится выбранным автоматически.
- Автоматическое и ручное озвучивание могут использовать выбранный локальный голос Piper; системный голос Windows остаётся резервным вариантом. Загруженный голос синтезирует речь на компьютере и не отправляет текст в интернет.
- Движок Piper 1.8.0 и ONNX Runtime включены в сценарий сборки EXE; голосовые модели по запросу загружаются отдельно (примерно 60–65 МБ на голос).

- Добавлены отдельные PNG-иконки разных размеров и явная установка больших/малых Win32-значков окна, чтобы улучшить отображение в панели задач на экранах с высоким DPI.
- Сохранены имя версии 4.1.2, поиск и удаление выбранных старых EXE-копий, а также защита текущего запущенного EXE от удаления.

## Версия 4.1.3 — облачная архитектура Google Drive + резервный Supabase

- Google Drive добавлен как основной облачный провайдер; приложение создаёт видимую папку `Моя ИИшка Cloud` и хранит там зашифрованный снимок.
- OAuth 2.0 Desktop flow использует loopback callback + PKCE и ограниченный scope `drive.file`.
- Google OAuth-сессия сохраняется через Windows DPAPI; E2E-пароль остаётся только на устройстве.
- Добавлен мягкий лимит папки приложения (по умолчанию 10 ГБ). Это не квота аккаунта Google: стандартные 15 ГБ разделяются между Drive, Gmail и Photos.
- Существующий Supabase может зеркалировать снимок и работать как резервный провайдер при недоступности Google Drive.
- Добавлено руководство `GOOGLE_DRIVE_SETUP_RU.md` и тесты `tests/test_google_drive_sync.py`.
- Уточнено, что текущий единый vault snapshot ограничен 20 МБ после сжатия; 10 ГБ — лимит папки приложения для будущих архивных объектов, не размер одной текущей записи.


## 4.1.3 — уточнение лимита Google Drive и документации резервного облака

- Мягкий лимит папки приложения ограничен 10 ГБ; доступны варианты 5, 8 и 10 ГБ. 10 ГБ остаётся настройкой по умолчанию.
- Уточнено, что Google Drive — основной провайдер, Supabase — необязательное резервное облако и failover.
- Руководство Supabase переименовано и обновлено как инструкция настройки резервной копии.

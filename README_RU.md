# Моя ИИшка 4.1.5.1

**Версия:** 4.1.5.1  
**Платформы:** Windows 10 / Windows 11  
**Интерфейс:** русский  
**Лицензия исходного проекта:** MIT

«Моя ИИшка» — настольное приложение с настраиваемым характером, памятью, отдельными диалогами, веб-исследованиями, голосовым управлением и инструментами расширения. В версии 4.1.3 добавлены Google Drive как основное облако, Supabase как резервный провайдер, сквозное шифрование, автоматическая синхронизация, фоновое пополнение библиотеки знаний и адаптивный регулятор нагрузки для ПК с 24 ГБ ОЗУ. В версии 4.1.5.1 исправлена упаковка модуля криптографии в EXE и обновлены GitHub Actions до Node.js 24. Версия 4.1.4 добавила транзакционную установку обновлений Windows с проверкой фактического пути и откатом. В версии 4.1.1 выровнены цвета карточек и подписей, улучшена читаемость страницы веб-исследований. В версии 4.1 обновлён интерфейс: контрастная боковая панель, быстрые стартовые действия, отдельная поверхность чата, более удобная область ввода, выравнивание сообщений и адаптация размера окна к экрану.


## Важное для сборки 4.1.5.1

После обновления репозитория обязательно замените `.github/workflows/release.yml`. Новый запуск должен называться **Build Windows release — verified 4.1.5.1**. Если отображается старое имя `Build Windows release` и предупреждения про `checkout@v4`, `setup-python@v5` или `softprops/action-gh-release@v2`, GitHub всё ещё выполняет прежний workflow — изменения workflow не отправлены в `main`.

Сборка использует Python из `actions/setup-python`, устанавливает зависимости из `requirements.txt` и проверяет криптографические импорты внутри собранного EXE. Публикация запрещена, если EXE не проходит `--self-test-imports`. Для этой сборки используйте тег `v4.1.5.1`.


## Что умеет приложение

- **Онлайн- и локальная модель.** Совместимый Chat Completions API или локальная модель через Ollama. Модель не входит в приложение. API-ключ не нужен для поиска в интернете; он требуется только для генеративных ответов облачной модели.
- **Интернет-исследования.** Бесплатный поиск без API-ключа: сначала Bing RSS, затем DuckDuckGo как резервный источник. Приложение читает ограниченное число общедоступных страниц, сохраняет ссылки и выдержки в локальную библиотеку. Вопросы со словами «сегодня», «сейчас», «последние новости», «актуальный» и явные команды «поищи в интернете…» могут автоматически запускать поиск.
- **Периодическое исследование.** В профиле 4.1.3 по умолчанию заданы четыре темы с интервалом 3 часа, до 10 результатов и чтением не более 5 страниц на тему за цикл. Список тем, частоту и объём можно изменить или выключить на странице «Интернет и знания». Результаты пополняют базу знаний и при подключённом облаке отправляются туда в зашифрованном виде.
- **Память.** Отдельные сохранённые факты, автоматическое извлечение из некоторых явных фраз, просмотр, редактирование и удаление.
- **Голос.** Голосовой ввод на русском, системный голос Windows и загружаемые русские голоса Piper. Голоса Ирина, Денис, Дмитрий и Руслан можно скачать из окна приложения; после загрузки озвучивание работает локально и без передачи текста в интернет. Микрофон выключен по умолчанию, постоянного прослушивания нет. Для записи надо явно разрешить микрофон и нажать «Начать говорить»; кнопка остановки отменяет запись и выключает разрешение в приложении. Движок Piper версии 1.8.0 лицензируется GPL-3.0-or-later; подробности и файлы лицензии находятся в `THIRD_PARTY_NOTICES.md` и `licenses/GPL-3.0.txt`.
- **Windows.** Запуск поддерживаемых программ и открытие стандартных папок из фиксированного разрешённого списка. Произвольные команды CMD/PowerShell не исполняются.
- **Персонаж.** Плавающее окно с анимированным персонажем.
- **Навыки и плагины.** Пользовательские JSON-навыки и собственные Python-плагины.
- **Саморазвитие.** Модель может подготовить diff для одного файла проекта. Перед применением пользователь видит изменения; создаётся резервная копия и запускаются проверки. Код не переписывается незаметно и без подтверждения.
- **Обновления.** Проверка GitHub Releases, проверка SHA-256, подтверждение установки и перезапуск EXE.
- **Облачное хранилище.** Google Drive — основное хранилище в видимой папке `Моя ИИшка Cloud`, Supabase — необязательная резервная копия и failover. Снимок сжимается и шифруется на устройстве AES-256-GCM до загрузки. Для Google используется узкий OAuth scope `drive.file`; токены хранятся под Windows DPAPI. Подключение — в `GOOGLE_DRIVE_SETUP_RU.md`; Supabase — в `SUPABASE_SETUP_RU.md`.
- **Диалоги.** История чатов в SQLite, поиск, переименование, экспорт и удаление.

## 1. Облачное хранилище (Google Drive основной, Supabase резервный, E2E)

Основной провайдер — Google Drive. Приложение создаёт видимую папку `Моя ИИшка Cloud` и сохраняет в ней зашифрованный файл `moyaishka-vault.enc`. Используется только OAuth scope `drive.file`: программа получает доступ к файлам, созданным ею самой, а не ко всему диску. Пароль E2E не отправляется Google. Отдельная настройка OAuth Desktop Client и пошаговое подключение описаны в [`GOOGLE_DRIVE_SETUP_RU.md`](GOOGLE_DRIVE_SETUP_RU.md).

Стандартный личный Google Account получает до 15 ГБ общего пространства на Google Drive, Gmail и Google Photos; эти 15 ГБ не являются отдельной квотой только для Drive. В приложении можно задать мягкий лимит папки ИИшки 5, 8 или 10 ГБ (по умолчанию и максимуму 10 ГБ). Он ограничивает собственные файлы приложения и не резервирует место у Google. Фактический доступный остаток зависит от использования Gmail, Photos и других файлов. Официальная справка: https://support.google.com/googleone/answer/9004014.

Supabase — необязательное резервное хранилище. При его подключении «Моя ИИшка» зеркалирует в него зашифрованную копию, а если Google Drive временно недоступен, может использовать Supabase для синхронизации. Для Supabase Free учитывайте 500 МБ Database size и 1 ГБ Storage — в текущей реализации снимок хранится в таблице PostgreSQL, а не в Storage bucket. Подробности — в [`SUPABASE_SETUP_RU.md`](SUPABASE_SETUP_RU.md), SQL — в `sql/supabase_setup.sql`.

Содержимое сжимается и шифруется на устройстве Scrypt + AES-256-GCM до отправки. Пароль E2E не хранится на сервере; на Windows OAuth-сессии защищаются DPAPI. Не теряй E2E-фразу: восстановить данные без неё невозможно. API-ключи LLM, пароли аккаунтов и аудио микрофона в снимок не включаются.

Автосинхронизация запускается после изменений и проверяет облако примерно раз в 5 минут. Если сети нет, локальная копия остаётся доступной; синхронизация продолжится позже. Текущий единый зашифрованный снимок ограничен 20 МБ после сжатия и 96 МБ после распаковки. Порог 10 ГБ — лимит папки приложения для будущих архивных объектов, а не размер одной текущей базы-снимка. Локальная база не удаляется.

OneDrive и S3 предусмотрены как возможные будущие адаптеры, но в версии 4.1.5.1 реально подключаемый резервный провайдер — Supabase. Отключение облака на ПК не удаляет удалённые файлы.

## 2. Профиль производительности для Intel i7-12700K / 24 ГБ RAM / GTX 1070 Ti

- Фоновый бюджет ИИ-процессов — **до 5120 МБ (5 ГБ)**. Это мягкий порог для планировщика приложения, а не жёсткий лимит Windows: фоновые задачи останавливаются примерно при 90% бюджета.
- Резервируется не менее **8 ГБ свободной физической памяти** для Windows и других приложений. При превышении порога CPU (по умолчанию 85%) фоновые исследования и облачные передачи ждут снижения нагрузки.
- Веб-исследование и облачные worker-потоки запускаются с низким приоритетом; основной интерфейс остаётся обычного приоритета.
- Для локальной Ollama по умолчанию используется 4 CPU-потока и контекст 4096 токенов; при обнаруженной нагрузке — 2 потока и 1536 токенов, генерация ограничена 384 токенами за ответ. Модель выгружается через короткий `keep_alive` (2 минуты).
- GTX 1070 Ti используется Ollama автоматически, если установленный драйвер/runtime поддерживает ускорение. Приложение не обещает жёсткого контроля VRAM: ресурсный регулятор отслеживает системную RAM и CPU.

Порог 5 ГБ — верхняя граница бюджета ИИ, а не цель постоянного потребления. Если компьютер активно занят другими программами, фоновые задачи приостанавливаются.

## 3. Запуск и самостоятельный EXE

### Самостоятельный EXE без Python на целевом компьютере

На компьютере, где выполняется сборка, установите **Python 3.11 x64** и подключение к интернету. Запустите `BUILD_EXE.bat`. Скрипт устанавливает необходимые библиотеки в среду сборки и создаёт:

```text
dist\MoyaIshka.exe
```

Это сборка `--onefile`: интерпретатор Python, интерфейс, движки голосового ввода/озвучивания и документные библиотеки включаются в один EXE. На компьютере пользователя отдельно устанавливать Python, PyAudio, SpeechRecognition, pyttsx3 или Piper не требуется. Отдельное голосовое приложение запускать не нужно. Сами голосовые модели (примерно 60–65 МБ каждая) загружаются по желанию прямо из раздела «Windows и голос» и сохраняются в `%APPDATA%\MoyaIshka\voices\piper`.

**Важное ограничение:** в EXE не включена большая языковая модель. Для ответов нужен либо онлайн API с собственным ключом, либо локальный LLM-runtime и загруженная модель. Ни один установщик приложения не может получить «бесплатный и безлимитный ИИ» только из Python-кода. Сборка EXE должна выполняться на Windows; в текущем пакете EXE ещё не собран.

### Запуск из исходников

Для подключения Google Drive см. [`GOOGLE_DRIVE_SETUP_RU.md`](GOOGLE_DRIVE_SETUP_RU.md); резервный Supabase настраивается по [`SUPABASE_SETUP_RU.md`](SUPABASE_SETUP_RU.md).

1. Распакуйте архив в отдельную папку, например `C:\Apps\MoyaIshka`.
2. Установите Python 3.11 x64 с компонентом Tcl/Tk.
3. Запустите `START.bat`.

Для чтения PDF/DOCX и голосовых функций при запуске из исходников нужны пакеты из `requirements.txt`. Команда `INSTALL_VOICE.bat` устанавливает голосовые зависимости в среду разработки. В самостоятельном EXE движки озвучивания и распознавания упакованы сборщиком; отдельно через приложение скачиваются только выбранные модели голосов.

## 4. Подключение ИИ

Важное различие: поиск общедоступных страниц не требует ключа и работает отдельно от языковой модели. Если ни облачная модель, ни локальная Ollama не подключены, ИИшка показывает найденные ссылки и выдержки. Для свободно сформулированного ответа по материалам нужна языковая модель.

### Онлайн API

В разделе «Настройки» укажите:

- URL совместимого Chat Completions API;
- имя модели;
- API-ключ.

Ключ на Windows хранится с защитой DPAPI текущей учётной записи. Использование API может тарифицироваться отдельно; подписка ChatGPT не является API-кредитом.

### Локальный режим через Ollama

Локальный LLM-runtime Ollama и сама модель не входят в этот EXE. Для локального ИИ их надо установить и скачать отдельно. Пример команды для загрузки небольшой модели:

```cmd
ollama pull qwen2.5:3b
```

Затем в настройках выберите «Только локально», адрес `http://localhost:11434`, имя модели `qwen2.5:3b` и проверьте подключение.

## Устранение ошибки WinError 10061 при подключении к Ollama

Эта ошибка означает, что приложение не нашло запущенный локальный сервер Ollama на `localhost:11434`. Если выбрана локальная модель:

1. Запустите приложение Ollama из меню «Пуск» Windows.
2. Откройте CMD и проверьте модели командой `ollama list`.
3. При необходимости загрузите модель: `ollama pull qwen2.5:3b`.
4. Если сервер всё ещё не отвечает, выполните `ollama serve` в отдельном окне терминала (не запускайте второй сервер, если Ollama уже работает).
5. В настройках ИИшки укажите адрес `http://localhost:11434` и точное имя установленной модели.

Для локального режима Ollama — отдельная программа. Если не хотите устанавливать её, выберите онлайн API и укажите собственный API-ключ. В готовом однофайловом EXE уже будут Python и голосовые библиотеки, но языковая модель в него не включена.

## 5. Интернет и автономное исследование

Откройте страницу **«Интернет и знания»**. Можно:

1. Включить или выключить веб-поиск.
2. Запустить исследование по конкретному запросу.
3. Задать темы для периодического исследования и интервал от 1 до 48 часов.
4. Ограничить число результатов и извлекаемых страниц.
5. Просматривать, открывать и удалять источники из локальной библиотеки.

Поиск в интернете выполняется без API-ключа. Если языковая модель не настроена, ИИшка покажет найденные материалы и выдержки напрямую. Если подключена Ollama, она сможет дополнительно сформулировать ответ локально; облачная модель использует ключ провайдера.

В чате можно написать, например:

```text
Поищи в интернете последние обновления Python 3.13
```

Или задать актуальный вопрос со словами «сегодня», «сейчас», «последние новости» и подобными маркерами, если включён автопоиск текущих данных.

**Это не безграничный веб-доступ.** Поиск использует публичную RSS-ленту Bing, а при её недоступности — HTML-страницу DuckDuckGo. Это не гарантированные и не версионируемые API: провайдеры могут ограничивать автоматические запросы или менять формат. RSS-результаты Bing применяйте для личного некоммерческого использования в соответствии с условиями RSS. Чтение ограничено числом и размером страниц, а внутренние адреса и локальная сеть блокируются. Сайты могут требовать вход, JavaScript, CAPTCHA или запрещать автоматическое чтение. Содержимое страниц считается недоверенным текстом: команды и инструкции сайтов не исполняются. Сохранённая база знаний пополняет контекст модели, но не переобучает её веса.

## 6. Голос и микрофон

Перейдите в **«Windows и голос»**.

### Загрузка голоса для озвучивания ответов

1. В блоке **«Голоса озвучивания ответов»** выберите голос: Ирина, Денис, Дмитрий или Руслан.
2. Нажмите **«Загрузить голос»** и подтвердите загрузку. Модель занимает около 60–65 МБ.
3. Дождитесь завершения загрузки и проверки SHA-256. После успешной проверки голос автоматически становится активным.
4. Нажмите **«Прослушать пример»**, чтобы проверить звучание. Для автоматического чтения новых ответов включите **«Автоматически озвучивать ответы»**.
5. Чтобы удалить загруженную модель, выберите её и нажмите **«Удалить голос»**. Можно вернуться к системному голосу кнопкой **«Использовать системный голос Windows»**.

Голосовые модели хранятся в `%APPDATA%\MoyaIshka\voices\piper`. Их нужно скачать только один раз. После этого выбранный голос синтезирует речь локально, без отправки текста в интернет и без отдельного голосового приложения. Для первичной загрузки требуется интернет.

Встроенный движок Piper 1.8.0 и ONNX Runtime упаковываются в EXE. Голоса — отдельные модели, которые пользователь выбирает и загружает из приложения. В каталоге версии 4.1.2 доступны четыре русских голоса среднего качества. Пакет Piper TTS распространяется по GPL-3.0-or-later, поэтому в релиз прикладываются уведомление, текст лицензии и исходный архив Piper TTS точной версии. Прочитай `THIRD_PARTY_NOTICES.md` перед самостоятельным распространением сборки.

### Микрофон и распознавание речи

- По умолчанию доступ приложения к микрофону выключен.
- Включите переключатель разрешения только тогда, когда хотите использовать голос.
- Нажмите «Начать говорить» — запись начнётся только после этого действия.
- Нажмите «Остановить и отключить микрофон», чтобы запросить прекращение активной записи и выключить разрешение внутри приложения.
- В любой момент можно открыть системные настройки конфиденциальности микрофона Windows.

Распознавание речи в этой сборке использует Google Speech Recognition: аудиофрагмент отправляется сервису через интернет. Сама запись не ведётся постоянно. Системный голос Windows и загружаемые голоса Piper работают локально. Переключатель приложения не заменяет системное разрешение Windows и не выключает микрофон для других программ.

## 7. Управление Windows

Страница **«Windows и голос»** содержит кнопки для запуска поддерживаемых приложений и открытия стандартных папок Windows. Через чат/распознавание понимаются команды наподобие «открой калькулятор» или «открой папку Загрузки». Приложение не запускает произвольный текст как команду оболочки и не выполняет опасные системные команды.

## 8. Память

Страница **«Память»** хранит полезные факты в `%APPDATA%\MoyaIshka\config.json`. Автоматическое извлечение основано на ограниченных шаблонах и может ошибаться. Память можно выключить, вручную дополнить, редактировать и полностью очистить. При использовании облачной модели выбранный контекст отправляется её провайдеру.

## 9. Навыки, плагины и саморазвитие

### JSON-навыки

Навыки — дополнительные текстовые инструкции, которые добавляются к контексту модели. Их можно создать и включить/выключить через «Навыки и развитие».

### Python-плагины

Плагины могут обрабатывать slash-команды. Их выполнение по умолчанию выключено. **Python-плагины не изолированы:** разрешённый файл может выполнять код с правами текущего пользователя Windows. Включайте только собственный или полностью проверенный код.

### Саморазвитие

Выберите файл проекта и опишите улучшение. Модель подготовит unified diff. Просмотрите его и только затем нажмите «Применить проверенный diff». Перед записью создаётся резервная копия, затем выполняются проверка синтаксиса и тесты. При ошибке проверок изменение откатывается. Это контролируемое изменение исходников, а не самостоятельное бесконтрольное переписывание приложения.

## 10. Автоматические обновления

В проект входит `.github/workflows/release.yml`.

1. Создайте репозиторий GitHub и загрузите в него проект.
2. Проверьте, что GitHub Actions разрешено создавать релизы (`Settings → Actions → General → Workflow permissions → Read and write permissions`).
3. Создайте и отправьте тег `v4.1.5.1` для этой сборки (следующие сборки получают следующий номер версии). GitHub Actions соберёт Windows EXE и опубликует `MoyaIshka.exe` и `MoyaIshka.exe.sha256`.
4. В настройках ИИшки уже предложен репозиторий `MrNike227/MoyaIshka_v4.1.1` (его можно изменить), выберите постоянную папку установки, нажмите «Сохранить настройки обновлений» и включите проверку обновлений. Путь сохраняется в локальной конфигурации и используется для всех последующих обновлений. Кнопка «Установить текущую версию сюда» переносит текущий EXE в выбранную папку; при запуске из исходников она только сохраняет место для первой автономной EXE-сборки.
В блоке обновлений есть кнопка **«Поиск устаревших версий»**. Она ищет EXE-копии приложения в известных пользовательских папках (папка установки, `%LOCALAPPDATA%\Programs`, папка обновлений, Рабочий стол и Загрузки). Текущая запущенная копия исключается. Найденные файлы отображаются с путём, размером и датой изменения. Для удаления нужно самостоятельно выбрать одну или несколько копий и подтвердить действие. Удаляются только выбранные EXE; настройки, история диалогов и база знаний не удаляются. Весь диск автоматически не сканируется.

Иконка `app_icon.ico` содержит отдельные варианты 16, 20, 24, 32, 40, 48, 64, 128 и 256 px, а исходный PNG сохранён в 1024×1024. Сборщик EXE и установщик используют этот ICO. Стабильный Windows AppUserModelID помогает Windows сохранять правильную иконку в панели задач после обновлений.

Приложение проверяет номер версии и SHA-256, затем предлагает установить обновление. При первом обновлении пользователь выбирает постоянную папку; этот путь сохраняется в `%APPDATA%\MoyaIshka\config.json` и используется для следующих версий. При запуске из `START.bat` автономный EXE ставится в выбранную папку, исходное окно закрывается, а новая версия запускается автоматически. В упакованной версии отдельный PowerShell-процесс ждёт закрытия старого приложения, повторно проверяет SHA-256, заменяет EXE в выбранной папке, сохраняет резервную копию `MoyaIshka.previous.exe` и запускает новую версию. Если приложение впервые запущено из старой папки `update_staging`, оно предлагает выбрать постоянную папку и переносит туда EXE. SHA-256 проверяет совпадение с опубликованной контрольной суммой, но не заменяет цифровую подпись издателя.

## Исправление 4.1.2: интернет-поиск без API-ключа

В чат-поиске поиск и генерация ответа разделены. Сначала приложение получает общедоступные результаты и сохраняет источники; затем пытается использовать подключённую модель. Если API-ключ не задан, облачная модель недоступна или Ollama не запущена, приложение больше не завершает поиск ошибкой подключения — оно отвечает списком источников, краткими выдержками и URL. API-ключ по-прежнему нужен для обычных генеративных ответов от облачной модели, но не для веб-поиска. Для бесплатного генеративного синтеза можно настроить локальную Ollama.

## Проверки и ограничения сборки

- Синтаксис Python проверен через `compileall`.
- Автоматические тесты: **64 passed** в проверке этой сборки; тесты загрузки голосов используют фиктивные данные и не скачивают 60-МБ модели.
- Интерфейс запускается в тестовой графической среде, проверены экран чата, страницы исследований/настроек, Enter/Shift+Enter и прокрутка областей под курсором.
- Финальный Windows EXE в этой среде не собран и не проверен на реальном Windows 10. Для него предусмотрен `BUILD_EXE.bat` и GitHub Actions. Piper TTS 1.8.0 публикует Windows x64 wheel для Python 3.9 ABI3 и новее; EXE в GitHub Actions должен собираться именно на Windows runner.
- Встроенная большая языковая модель отсутствует; необходимо настроить онлайн API или локальную модель.


## Исправление 4.1.2: резервные поисковые системы без API-ключа

Поиск больше не зависит только от DuckDuckGo. Сначала используется RSS-лента Bing (XML, без API-ключа); если она недоступна, заблокирована или вернула неожиданный формат, приложение автоматически пробует DuckDuckGo. Если оба источника не работают, окно ошибки показывает причину отдельно для каждого провайдера, а не сообщает, что результатов просто нет. Поиск остаётся ограниченным и может зависеть от региональной доступности, сетевых фильтров и изменений самих поисковых сайтов.


## Надёжное обновление EXE в версии 4.1.5.1

- Постоянная папка установки хранится в `%APPDATA%\MoyaIshka\config.json` в поле `install_dir`; сама программа и обновления используют именно `install_dir\MoyaIshka.exe`.
- Скачанный файл сначала находится в `%APPDATA%\MoyaIshka\update_staging`, но это только временное место. Он не считается установленным, пока новая программа не запустится из выбранной папки и не подтвердит версию, путь и SHA-256.
- Если из старой версии пользователь вручную запустит EXE из `update_staging`, новая версия передаст установку отдельному PowerShell-процессу. Он дождётся выхода запущенных экземпляров, аккуратно закроет старый экземпляр из целевой папки, создаст резервную копию и заменит EXE.
- Журнал установки: `%APPDATA%\MoyaIshka\update.log`. Он создаётся ещё до запуска PowerShell; если AppData недоступен, установщик дополнительно пишет `update.log` рядом с целевым EXE. В настройках есть кнопка «Открыть журнал обновлений».
- Пустые поля `FileVersion`/`ProductVersion` в свойствах Windows сами по себе не блокируют установку. Итоговая проверка выполняется после запуска: программа сверяет `APP_VERSION`, фактический путь EXE и SHA-256 с данными релиза. Если заполненные Windows-метаданные явно указывают на другую версию, обновление отклоняется.
- Резервная копия предыдущей версии: `MoyaIshka.previous.exe` в папке установки. При неудачной проверке программа восстанавливается из неё.
- Для перехода со старых сборок 4.1.2/4.1.3 один раз скачайте EXE версии 4.1.5.1 из GitHub Releases. Если старый updater сохранил его в `%APPDATA%\MoyaIshka\update_staging`, запустите именно этот новый EXE. Он не копирует себя поверх работающего файла: отдельный установщик дождётся выхода нового процесса, попросит старый экземпляр из `D:\ISH` закрыться и атомарно заменит `D:\ISH\MoyaIshka.exe`.
- Перед установкой убедитесь, что в настройках сохранена нужная папка, например `D:\ISH`. Если старый экземпляр не отвечает на запрос закрытия, установка остановится, оставит прежний EXE и запишет причину в журнал.

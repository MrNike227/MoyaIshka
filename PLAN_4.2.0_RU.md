# План версии 4.2.0 — безопасный ИИ-агент

Статус: проектирование и реализация в ветке \`feature/4.2.0\`.

## Почему это следующий шаг

В 4.1.9 уже есть интеллектуальная память, веб-исследования и библиотека знаний, разрешённые действия Windows, навыки и Python-плагины, саморазвитие, облачная синхронизация и резервное копирование. Следующее полезное развитие — связать эти возможности в контролируемый процесс выполнения составных задач.

## Предлагаемый объём

### 1. Планирование

Модель формирует структурированный план, а приложение проверяет его до выполнения:
- понятная цель;
- от 1 до 8 шагов;
- тип инструмента из белого списка;
- входные данные с ограничениями длины и формата;
- ожидаемый результат;
- уровень риска и необходимость подтверждения.

Невалидный JSON, неизвестный инструмент, лишние поля и превышение лимитов отклоняются. План не должен исполняться напрямую как текст модели.

### 2. Реестр инструментов

Начать с ограниченного набора встроенных операций:
- поиск по сохранённой памяти и базе знаний;
- интернет-поиск и открытие результатов через существующий безопасный механизм;
- просмотр сведений о поддерживаемых приложениях и стандартных папках;
- открытие приложения или стандартной папки через текущий allowlist Windows.

Любой инструмент получает строгую схему аргументов, тайм-аут, уровень риска и проверку результата. Плагины не получают автоматический доступ только потому, что модель упомянула их в плане.

### 3. Согласование действий

Предлагаемые уровни:
- **Низкий риск:** чтение памяти/знаний, поиск, подготовка плана.
- **Ограниченное действие:** открытие приложения или стандартной папки из разрешённого списка.
- **Изменение данных:** создание, перезапись, перемещение и удаление файлов, изменение настроек или запуск кода — отдельное подтверждение с показом точного действия.
- **Запрещено для MVP:** произвольные CMD/PowerShell-команды, выполнение неизвестного кода, скрытая установка программ и самостоятельное применение изменений исходников.

Подтверждение должно быть привязано к конкретному шагу и его аргументам. Изменение плана после подтверждения требует нового согласия.

### 4. Выполнение и проверка

- Одновременно выполняется не более одного шага.
- У каждого шага есть состояния: ожидание, запрос подтверждения, выполнение, успех, ошибка, отмена.
- Ограниченное число повторов только для повторяемых и безопасных операций.
- Кнопки остановки и отмены; отмена не должна оставлять ложный статус «выполнено».
- После инструмента запускается независимая проверка его результата.
- Итоговый ответ формируется по реальным результатам, а не по обещанию модели.

### 5. Журнал и восстановление

Локальный журнал хранит ID задачи, время, шаги, типы инструментов, итог и краткую причину ошибки. Секреты, токены и полные содержимые чувствительных файлов не записываются. Историю задач можно очищать и экспортировать. Перед изменяющими действиями используются существующие резервные механизмы; состояние незавершённой задачи не должно автоматически повторять опасное действие после перезапуска.

### 6. Разрешения плагинов

Сначала добавить каталог разрешений для каждого плагина, отдельный запрос согласия, тайм-аут, ограничение вывода и журнал запуска. Вызов Python-плагина не должен выполняться автоматически из текста ответа модели. Отдельный процесс уменьшает риск зависания, но сам по себе не является полноценной песочницей ОС; это ограничение нужно явно документировать.

## Порядок реализации

1. Контракт плана и валидатор схемы.
2. Реестр встроенных инструментов и классификация риска.
3. Окно предпросмотра плана и подтверждение шагов.
4. Последовательный исполнитель с отменой и проверкой результата.
5. Журнал задач и сохранение истории.
6. Разрешения плагинов и тесты безопасности.

## Критерии готовности

- Модель не может вызвать инструмент вне реестра.
- Недоверенный текст из интернета, документов, памяти и плагинов трактуется как данные, а не как инструкции системе.
- Никакой опасный шаг не стартует до явного подтверждения.
- Невозможные, невалидные или просроченные действия корректно отклоняются.
- Ошибка и отмена не сообщаются как успех.
- Есть тесты на обход allowlist, подмену аргументов после подтверждения, тайм-ауты, повторы, отмену и отсутствие утечки секретов в журнал.
- Полный набор unit-тестов проходит; Windows onedir запускается без установленного Python.

## Что оставить на следующую версию

- Автоматический выбор лучшей модели для каждой задачи.
- Полноценную изоляцию Python-плагинов средствами Windows.
- Продвинутую голосовую активацию.
- Автоматическое изменение исходников без ручной проверки.

Эти направления не должны перегрузить первую реализацию агента и не заменяют обязательные проверки безопасности.

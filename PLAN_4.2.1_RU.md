# План версии 4.2.1 — безопасная доставка предложений саморазвития

## Общая структура каталогов

Корневая папка выбирается пользователем. В ней находятся два независимых каталога:

\`\`\`text
MoyaIshka/
  App/
    MoyaIshka.exe
    _internal/
    build_manifest.json
  Updates/
    Proposals/
      <timestamp>_<id>/
        manifest.json
        changes.patch
        files/
          main.py
\`\`\`

Обновлятор заменяет только \`App\`. Каталог \`Updates\` находится рядом и не участвует в удалении, переименовании или проверке манифеста установленной сборки. Старую установку не перемещать автоматически: миграция выполняется отдельной командой после подтверждения пользователя.

## Режим 1. Сохранить изменения локально

- После генерации diff пользователь выбирает «Сохранить изменённые файлы в Updates».
- Diff проверяется на точное применение к текущему локальному исходнику; Python-код компилируется до сохранения.
- Пакет сохраняет полный изменённый файл, diff, исходный и новый SHA-256, версию приложения и статус \`review_only_not_applied\`.
- Пакет создаётся атомарно во временной папке и переименовывается целиком после успешной записи.
- Существующие файлы не перезаписываются. Каждое предложение получает отдельную папку.
- Сохранение не применяет изменения к рабочему приложению.

## Режим 2. Создать GitHub Draft PR без релиза

- Пользователь задаёт репозиторий и базовую ветку, а также сохраняет Fine-grained PAT.
- Нужные разрешения: Metadata — Read-only, Contents — Read and write, Pull requests — Read and write.
- Windows хранит токен DPAPI текущей учётной записи.
- Перед публикацией программа читает текущий файл из GitHub base branch и пытается применить локальный diff к этой версии. При конфликте прекращает процесс и просит повторно получить diff.
- Создаёт новую ветку \`moya-improvement/<id>\`, blob, tree, commit и Draft PR.
- Не вызывает API создания release/tag, merge или push непосредственно в base branch.
- При неудаче создания PR пытается удалить созданную ветку.
- В интерфейсе показывает ссылку на готовый Draft PR.

## Проверки безопасности и надёжности

- Запрещены абсолютные и traversal-пути; локальный режим ограничен Python-файлами.
- Ограничены максимальный размер файла, diff и пакета.
- PAT не попадает в лог, манифест, diff и описание PR.
- PR создаётся только после явного подтверждения пользователя.
- Недоверенный diff проверяется локальным парсером и компилятором и сверяется с GitHub base.
- Токен не включается в облачные снимки, резервные архивы или bundle.
- Отсутствие токена не мешает локальному сохранению пакета.
- Любая сетевая ошибка не меняет локальный исходник и не выполняет прямой commit в main.

## Критерии готовности

1. App и Updates — соседние каталоги, Updates не является потомком App.
2. Обновление App не удаляет и не затрагивает Updates.
3. Локальный пакет содержит полный изменённый файл, diff и совпадающие SHA-256.
4. Traversal-пути и некорректный Python отвергаются до сохранения.
5. GitHub Draft PR создаёт только отдельную ветку и PR в состоянии draft.
6. Несовместимый diff не создаёт ветку, commit или PR.
7. Никакой токен не присутствует в логах/метаданных.
8. Полный набор unit-тестов и Windows onedir-проверки проходят.

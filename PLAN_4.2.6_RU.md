# Версия 4.2.6 — безопасное фоновое саморазвитие

## Цель

Разрешить Моя ИИшке готовить и проверять предложения кода, не запуская сгенерированный код с правами основной учётной записи Windows.

## Установка Windows Sandbox из приложения

- В разделе «Навыки, плагины и развитие» приложение показывает состояние Windows Sandbox.
- Кнопка установки включает встроенный компонент Windows `Containers-DisposableClientVM` через видимый запрос UAC.
- Фоновая проверка состояния выполняется без административных прав: используется CIM для проверки виртуализации, запущенного гипервизора, ОЗУ, логических процессоров и времени последней загрузки Windows.
- Повышенные права запрашиваются только для включения системного компонента. Команда передаётся PowerShell как inline EncodedCommand, а не как изменяемый PS1-файл из пользовательской временной папки.
- Результат установки и время загрузки сохраняются в локальной отметке; после перезагрузки приложение сравнивает время загрузки и снимает блокировку только после повторной проверки готовности.
- Никакого обхода UAC, скрытой выдачи прав и самостоятельной перезагрузки нет.
- Если Windows сообщает о необходимости перезагрузки, приложение сохраняет статус «ожидает перезагрузки» и блокирует тесты до повторной проверки после перезапуска.
- Если редакция Windows, версия сборки, виртуализация или гипервизор не поддерживаются/не готовы, приложение показывает причину и не запускает код.

## Изоляция тестирования

- На основном компьютере выполняются только проверки путей, манифеста, SHA-256, diff и синтаксиса Python.
- Проект копируется во временный каталог, секреты, настройки, базы данных, облачные сессии, резервные копии, виртуальные окружения и символьные ссылки исключаются.
- В гостевую систему передаётся только временная копия проекта и отдельная копия onedir test-runner.
- В Windows Sandbox отключены сеть, буфер обмена, vGPU, аудио, видео и перенаправление принтеров; включён Protected Client (AppContainer isolation).
- Копия проекта и runner смонтированы только для чтения. На хост доступна только отдельная папка тестовых результатов.
- Тесты запускаются упакованным `MoyaIshka.exe`, чтобы использовать тот же встроенный Python/runtime, что и у пользователя; отдельный Python на компьютере пользователя не требуется.
- Время выполнения ограничено 10 минутами; при тайм-ауте результат считается неуспешным.
- Нет резервного запуска с правами пользователя. Если Sandbox не готова, тестирование завершается отказом.
- Успешный тестовый отчёт не устанавливает изменение: применение к установленной программе и создание PR остаются отдельными подтверждаемыми действиями.

## Границы гарантии

Windows Sandbox снижает риск от вредоносного/ошибочного тестового кода, но не является математической гарантией отсутствия уязвимостей гипервизора или самой Windows. Отчёт тестирования подтверждает конфигурацию среды и результат тестов, но не заменяет проверку кода человеком.

## Многофайловое саморазвитие

- Формат пакета допускает до 10 Python-файлов; каждый файл имеет собственные base SHA-256 и SHA-256 результата.
- Для пакета из нескольких файлов обязателен как минимум один файл программы и один соответствующий `tests/test_*.py`.
- Связанный тестовый файл разрешено обновить либо создать новым через `--- /dev/null`; новый файл должен отсутствовать в исходном проекте.
- Валидатор сверяет состав manifest и diff, хеш каждого файла, исходное состояние (включая отсутствие нового файла), синтаксис и точное применение каждого file hunk.
- Для тестирования все изменённые файлы накладываются на отдельную копию проекта внутри Windows Sandbox; затем выполняется полный набор unit-тестов, включая добавленный тест.
- Кнопка прямого применения и текущий экран Draft PR не выполняют многофайловый diff: сначала сохраняется и тестируется пакет. Это защищает от частичного применения пары «код + тест».

## Проверки

- Unit-тесты XML-конфигурации: сеть/буфер обмена выключены, project mapping read-only, outputs mapping отдельный и writable.
- Проверки отказа при недоступности Windows Sandbox и отсутствия локального fallback.
- Проверки исключения секретов и баз данных из временной копии.
- GitHub Actions проверяет полный набор unit-тестов и автономную onedir-сборку.
- Фактический запуск Windows Sandbox проверяется отдельно на Windows 10 Pro 22H2 с включённой Intel VT-x и после возможной перезагрузки. Microsoft указывает минимум 4 ГБ ОЗУ, 1 ГБ свободного места и два CPU-ядра; 8 ГБ ОЗУ и четыре ядра рекомендуются для комфортной работы.

## Ограничения текущего этапа

Фоновый разработчик `background_developer.py` подготовлен как отдельный модуль, но его полный планировщик и подключение к UI остаются отдельной задачей. Эта версия сосредоточена на безопасной установке и тестировании предложений. Автоматическое изменение исходников или установленной программы не включается.

# Настройка резервного облака «Моей ИИшки» 4.1.3 (Supabase + E2E)

Google Drive является основным облаком. Это руководство настраивает необязательную вторую зашифрованную копию и резервный маршрут через Supabase. Код приложения не содержит общего серверного пароля: каждый пользователь входит в свой Supabase Auth аккаунт, а содержимое шифруется на компьютере до отправки.

## 1. Создать проект Supabase

1. Откройте https://supabase.com/dashboard и войдите или зарегистрируйтесь.
2. Нажмите **New project**.
3. Выберите организацию, задайте имя проекта и сильный пароль базы данных. Пароль базы данных не нужен приложению и не должен вводиться в настройки ИИшки.
4. Выберите подходящий регион, предпочтительно в ЕС, если вы и большинство устройств находитесь в Европе.
5. Дождитесь создания проекта.

## 2. Создать таблицу зашифрованного хранилища

1. Откройте **SQL Editor → New query**.
2. Откройте файл `sql/supabase_setup.sql` из этого проекта.
3. Скопируйте весь SQL в редактор Supabase и нажмите **Run**.
4. В Table Editor должна появиться таблица `public.moyaishka_vault`.

Скрипт включает Row Level Security (RLS) и политики, разрешающие пользователю обращаться только к собственной строке (`auth.uid() = user_id`). Не отключайте RLS.

## 3. Получить публичные настройки приложения

В Supabase откройте **Project Settings → API** (или **Connect**, в зависимости от версии панели):

- Project URL — выглядит как `https://xxxxxxxx.supabase.co`.
- Publishable key (или устаревший `anon` key) — публичный ключ клиента.

В приложение нельзя вставлять `service_role`, `secret` или пароль PostgreSQL. Эти секреты дают привилегированный доступ и не должны находиться в настольном приложении.

## 4. Включить вход по электронной почте

1. Откройте **Authentication → Sign In / Providers → Email**.
2. Убедитесь, что Email-провайдер включён.
3. Оставьте подтверждение электронной почты включённым, если Supabase отправляет письма для вашего проекта.
4. Проверьте SMTP/параметры почты в Supabase, если письмо подтверждения не приходит.

## 5. Подключить резервное облако в приложении

Откройте **Настройки → Облачное хранилище → Резервное облако · Supabase** и заполните:

- URL проекта Supabase;
- публичный Publishable/anon key;
- адрес электронной почты;
- пароль аккаунта Supabase;
- отдельный пароль сквозного шифрования (не менее 10 символов; используйте длинную уникальную парольную фразу).

Нажмите **Создать резервный аккаунт**. Если приложение просит подтвердить адрес, откройте письмо Supabase. После подтверждения нажмите **Подключить резерв Supabase**. Google Drive остаётся основным провайдером, если он подключён.

Переключатель автоматической синхронизации включён по умолчанию. Изменения отправляются с небольшой задержкой после редактирования, а фоновая проверка облака выполняется примерно раз в 5 минут. Неизменённая копия не загружается повторно.

## 6. Что именно защищено

Перед отправкой приложение:

1. собирает выбранные диалоги, память, настройки и базу исследований;
2. сжимает JSON;
3. получает ключ из отдельной парольной фразы через Scrypt;
4. шифрует данные AES-256-GCM с новым nonce;
5. отправляет в Supabase только шифротекст, salt, nonce и версию формата.

Содержимое диалогов, памяти и исследовательских заметок не отправляется в открытом виде. Supabase всё равно видит адрес email/ID аккаунта, время изменения и технический размер зашифрованной записи.

Пароль шифрования **не хранится в Supabase**. На Windows запомненная сессия приложения защищается DPAPI в профиле текущего пользователя. На другом компьютере нужно снова ввести пароль шифрования. Запишите его в менеджер паролей: если забыть эту фразу, расшифровать облачные данные невозможно, сброс пароля аккаунта Supabase её не восстановит.

API-ключи языковых моделей, пароль аккаунта Supabase, пароль шифрования, аудио микрофона и локальные голосовые модели в облачную копию не включаются.

## 7. Поведение при отсутствии интернета и на нескольких компьютерах

- Локальная копия остаётся доступной, пока нет сети.
- После восстановления соединения синхронизация повторяется по таймеру или после нового изменения.
- Диалоги и сообщения объединяются по стабильным ID, поэтому новые записи с другого компьютера не должны затирать локальные.
- Одновременное изменение облачной строки защищено проверкой версии (optimistic concurrency); при конфликте приложение просит повторить синхронизацию.
- Удаление локальных записей не используется как команда удаления облачной копии: облако — резервная синхронизируемая копия, не средство гарантированного удалённого стирания.

## 8. Облачная библиотека и исследования

При подключённой автосинхронизации результаты фонового исследования, добавленные в базу знаний, попадают в зашифрованную облачную копию. Поиск выполняется без ключа облачной языковой модели; для связного генеративного ответа всё ещё нужна локальная Ollama или облачный LLM API.

В профиле 4.1.3 заданы четыре стартовые темы, интервал 3 часа, до 10 поисковых результатов и загрузка максимум 5 страниц на тему за цикл. В локальной библиотеке хранится до 1000 последних материалов. Это ограниченная и управляемая исследовательская очередь, а не непрерывное сканирование всего интернета. Остановите автоматическое исследование на странице «Интернет и знания», если оно не нужно.

## 9. Лимиты облачного плана (важно различать квоты)

В документации Supabase для Free указаны разные показатели, которые легко перепутать:

- **Database size:** 500 МБ данных БД на проект — это квота размера самой базы, в которой приложение хранит зашифрованный снимок в таблице `moyaishka_vault`.
- **Database disk:** фиксированный диск проекта 2 ГБ — это размер диска PostgreSQL, а не разрешённый объём пользовательских данных. Не следует планировать заполнение всего диска: место нужно PostgreSQL, WAL и служебным данным.
- **Supabase Storage:** отдельная квота файлового хранилища — 1 ГБ на Free. Текущая реализация приложения не использует этот bucket.
- **Egress:** бесплатная квота передачи данных ограничена; частые полные синхронизации больших снимков могут расходовать её.

Поэтому для текущей реализации ориентируйтесь на **500 МБ квоты Database size**, а не на 2 ГБ disk. Приложение сжимает снимок до отправки, ограничивает его размер 20 МБ и пропускает повторную загрузку, если содержимое не изменилось. Это ограничение защищает одну операцию синхронизации, но не является обещанием, что вся история поместится в квоту: контролируйте рост таблицы и архивируйте старые данные при необходимости.

Бесплатные проекты также могут приостанавливаться после периода неактивности. Перед размещением больших объёмов проверьте текущие ограничения в официальной документации: https://supabase.com/docs/guides/platform/billing-on-supabase и https://supabase.com/docs/guides/platform/database-size, а также https://supabase.com/pricing. Квоты и условия могут меняться.

## 10. Удаление/отключение

Кнопка **Отключить Supabase** удаляет только локальную защищённую сессию резервного провайдера; зашифрованная строка в Supabase не удаляется, а Google Drive продолжает быть основным облаком. Удаление облачной строки можно сделать отдельно через Supabase Dashboard после входа в нужный аккаунт. Сначала экспортируйте нужную информацию.

# Версия 4.2.8 — надёжная генерация diff и многофайловые Draft PR

## Исправление ошибки саморазвития

Сообщение «Не удалось получить корректный многофайловый diff после 3 попыток. В diff не найдены пары заголовков --- / +++» появлялось, когда модель возвращала пояснение, Markdown-кодблок, JSON-ответ, отдельные блоки для файлов или Git diff вместо ожидаемого объединённого unified diff.

- Diff извлекается из ответа в обычном тексте, Markdown code fences и JSON-полях diff/patch/unified_diff/content/output.
- Несколько отдельных code blocks объединяются перед разбором.
- Поддерживаются стандартные Git metadata и Git diff с заголовком diff --git, если модель пропустила стандартную пару --- / +++.
- При некорректном ответе выполняется повторный запрос с разрешёнными путями, точным примером заголовков и запретом выдавать полный файл вместо diff.
- Финальная ошибка показывает фрагмент последнего ответа, чтобы было видно, что вернула модель.

## Отправка проверенного пакета на GitHub

- Можно отправить несколько изменённых файлов, включая обновлённый или новый tests/test_*.py, одним Draft PR.
- Отправка разрешена только для пакета, сохранённого в Updates/Proposals и успешно проверенного в Windows Sandbox.
- Перед отправкой заново проверяются manifest, SHA-256, состав файлов, тестовый отчёт и отсутствие ссылок/reparse points.
- Для каждого файла запрашивается актуальная версия из выбранной базовой ветки GitHub. Базовый SHA-256 сверяется с тем, на котором было подготовлено предложение.
- Diff применяется к GitHub-версии; содержимое результата сверяется с протестированным файлом. При изменении исходника или несовпадении хотя бы одного файла PR не создаётся.
- Создаётся одна отдельная ветка и один Draft PR; main, релизы и теги не изменяются автоматически.

## Сохранённые ограничения

- До 10 Python-файлов на один пакет.
- Новые файлы разрешены только для tests/test_*.py.
- Удаление и переименование файлов запрещены.
- Саморазвитие не изменяет исходники и установленную программу автоматически.
- Windows Sandbox снижает риск запуска ошибочного кода, но не гарантирует абсолютную защиту от уязвимостей Windows/Hyper-V.

## Регрессионные проверки

Добавлены тесты на Markdown и JSON-обёртки, раздельные блоки diff, Git diff без пар заголовков, повтор генерации после некорректного ответа, отказ при изменённой базовой версии GitHub и отправку полного пакета одним Draft PR.

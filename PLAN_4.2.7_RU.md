# Версия 4.2.7 — исправление установки Windows Sandbox

## Причина ошибки

PowerShell создаёт `install_result.json` только после того, как пользователь подтвердил UAC и завершилось включение Windows Optional Feature. До этого приложение опрашивает путь каждую секунду. Предыдущая проверка считала `FileNotFoundError` при `Path.lstat()` признаком reparse point и прекращала ожидание сразу, хотя файл ещё не должен был существовать.

## Исправление

- Отсутствующий файл результата теперь означает «ожидание» и не вызывает ошибку безопасности.
- Если путь существует, он по-прежнему проверяется через `lstat()` без перехода по ссылке.
- Символические ссылки, Windows junction/reparse points и недоступные для проверки пути по-прежнему отклоняются (fail closed).
- После появления файла сохраняются прежние проверки размера, JSON-формата и типа поля `success`.
- Добавлены регрессионные тесты: отсутствующий путь не является reparse point; функция ожидания получает и разбирает результат после его создания PowerShell.

## Границы проверки

GitHub Actions проверяет поведение функции опроса и сборку Windows onedir. Фактическое включение компонента через UAC и последующий запуск Windows Sandbox необходимо отдельно проверить на Windows 10 Pro 22H2. Эта ветка не создаёт релиз и не изменяет существующий тег.

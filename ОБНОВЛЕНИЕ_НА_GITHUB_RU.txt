ОБНОВЛЕНИЕ «МОЯ ИИШКА» ДО ВЕРСИИ 4.1.4

Главное исправление:
- Исправлена запись PowerShell-установщика: UTF-8 BOM + корректный CRLF.
- Запуск EXE из %APPDATA%\MoyaIshka\update_staging теперь запускает отдельный установщик, а не пытается заменить работающий файл самим собой.
- Установщик дожидается выхода нового процесса и просит старый экземпляр из целевой папки закрыться.
- Новая копия проверяется по SHA-256 и встроенной версии EXE.
- Предыдущая копия сохраняется как MoyaIshka.previous.exe; если запуск новой версии не подтверждён, предыдущая копия восстанавливается.
- Приложение сообщает об успехе только после проверки фактической версии, пути запуска и SHA-256.
- Добавлен вывод фактического и целевого путей, кнопка открытия папки установки и кнопка открытия журнала обновлений.

Как обновить GitHub-репозиторий:
1. Сделайте резервную копию текущего репозитория и пользовательских данных.
2. Распакуйте ZIP проекта 4.1.4.
3. Скопируйте всё содержимое папки MoyaIshka_v4.1.4 в корень локального репозитория, соглашаясь на замену файлов. Не удаляйте .git.
4. Убедитесь, что main.py содержит APP_VERSION = "4.1.4" и version_info.txt содержит ProductVersion 4.1.4.
5. Сделайте Commit и Push.
6. Создайте новый тег v4.1.4 на ветке main и опубликуйте релиз.
7. На вкладке Actions дождитесь успешного тестирования и сборки.
8. В Releases дождитесь MoyaIshka.exe и MoyaIshka.exe.sha256.

Однократный переход со старой версии 4.1.2:
1. После публикации v4.1.4 скачайте новый EXE через старую ИИшку или из GitHub Releases.
2. Если старая версия оставила файл в %APPDATA%\MoyaIshka\update_staging, запустите именно новый EXE из этой папки.
3. Новый EXE передаст установку отдельному помощнику. Помощник закроет старую копию, заменит файл в сохранённой папке (например D:\ISH) и запустит новую версию.
4. После запуска появится сообщение с подтверждённой версией и фактическим путём.

Журнал обновлений:
%APPDATA%\MoyaIshka\update.log
В приложении есть кнопка «Открыть журнал обновлений».

Важно:
- Временная папка update_staging предназначена только для загрузки; она не является постоянной папкой установки.
- Не удаляйте MoyaIshka.previous.exe до успешной проверки новой версии.
- Если старая копия не закрывается, установщик отменит замену, оставит старый EXE и запишет причину в журнал.
- Самостоятельная Windows EXE-сборка выполняется на GitHub Actions или на Windows через BUILD_EXE.bat.
